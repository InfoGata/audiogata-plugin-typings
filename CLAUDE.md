# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`@infogata/audiogata-plugin-typings` — the ambient TypeScript declarations for the [AudioGata](https://github.com/InfoGata/audiogata) plugin API. The published package is essentially one file: `index.d.ts`. `index.js` is intentionally empty and `package.json` `main` is `""`; there is no build step and nothing is compiled or emitted.

Consumers pick the types up either via `"types": ["@infogata/audiogata-plugin-typings"]` in their tsconfig or by `import "@infogata/audiogata-plugin-typings"`.

## Commands

```sh
npm test                 # runs `tsc` (noEmit, strict) — the only check on index.d.ts

cd docs && npm start     # Docusaurus dev server; regenerates TypeDoc output on start
cd docs && npm run build # static build into docs/build
cd docs && npm run typecheck
```

There is no linter and no unit test suite. `npm test` type-checking `index.d.ts` is the entire CI gate.

## Architecture of `index.d.ts`

Everything lives inside a single `declare global { ... }` block with a trailing `export {}` — that combination is what makes the file a module that contributes globals rather than a script. Do not remove `export {}`, and do not add top-level imports (they would not change the pattern but nothing here needs them).

The global surface is:

- `const application: Application` — the object AudioGata injects into the plugin's iframe.
- `Application` mixes two very different things:
  - **Host-provided methods** the plugin calls (`networkRequest`, `getPlaylists`, `createNotification`, `postUiMessage`, `getCorsProxy`, …). These are always present.
  - **`on*` callbacks the plugin assigns** so AudioGata can call into it (`onSearchAll`, `onGetTrackUrl`, `onGetAlbumTracks`, `onPlay`, `onNowPlayingTracks*`, …). Most are optional; their doc comments state which AudioGata route or feature each one enables, and that mapping is the real contract — keep writing them when adding callbacks. Note a few callbacks (`onLookupTrack`, `onGetLyrics`, `onGetSearchSuggestions`, `onChangeTheme`) are declared non-optional, inconsistently with the rest.

Data model conventions that repeat across `Track` / `Album` / `Artist` / `PlaylistInfo`:

- `id` — generated by AudioGata, optional in plugin-returned data.
- `apiId` — the third-party service's id; this is what request interfaces (`GetTrackRequest`, `AlbumTrackRequest`, …) key off.
- `pluginId` — set by AudioGata, not the plugin.
- `originalUrl`, `images: ImageInfo[]` — the standard "link back" / artwork fields.

Paging and filtering are uniform: requests carry an optional `PageInfo` (and `FilterInfo` for searches), and every result type extends `SearchResult` (`pageInfo`, `filterInfo`) — e.g. `AlbumTracksResult extends SearchTrackResult` and just adds `album`. Follow that shape rather than inventing per-endpoint paging fields.

Because this is a published typings package that other plugin repos compile against, adding optional members is safe; renaming or tightening existing ones breaks downstream plugins.

## Docs site (`docs/`)

Docusaurus 3 with `docusaurus-plugin-typedoc`, deployed to GitHub Pages under `/audiogata-plugin-typings/`. The API reference is generated from `../index.d.ts` on every `start`/`build`, and **the generated markdown is committed** — the established commit pattern (see `97f75da`, `88f0c1c`) is: edit `index.d.ts`, run a docs build, commit `index.d.ts` together with the regenerated files under `docs/plugins/api/`.

Two gotchas here:

- The plugin's `out: "plugins/api"` resolves relative to the `docs/` site dir, so generated files land in `docs/plugins/api/` — *outside* the Docusaurus content dir (`docs/docs/`). `docs/docs/plugins/api/` is an older committed copy of the same output, left from before the output path changed, and is no longer regenerated; it is what the site content tree actually contains. Expect the two trees to diverge and check which one you are looking at.
- Generated markdown can break the MDX parser (bare `{`/`}` in doc comments). `4f8e131` fixed this by escaping (`\{url\}`) in the committed markdown, so a doc comment containing braces may need the same treatment after regeneration.

Hand-written docs pages are `docs/docs/intro.md` and `docs/docs/plugins/{installation,plugin-manifest}.md`.

## Releasing

Version bump is local, publish is CI (`.github/workflows/publish.yml`, npm OIDC trusted publishing — no `NPM_TOKEN`):

```sh
npm version <patch|minor|major>
git push --follow-tags
```

The workflow runs on `v*` tags, re-runs `npm test`, and fails if the tag does not match `package.json`'s version, then publishes and cuts a GitHub Release. `docs/` is excluded from the npm tarball via `.npmignore`.
